Neutralize

An AI-powered browser extension that detects rhetorical devices in webpages and PDFs, and rewrites them in neutral language.

ROLE Solo · Engineering + Design + PM
STACK Chrome MV3 · Firefox MV2 · Claude API · React · TypeScript · PDF.js
TIMELINE ~2 weeks, casual
STATUS ◈ Active
NTZ-CORE · v2.5.0 WEBPAGES + PDF SUPPORT WCAG AA · CVD-OPTIMIZED 7 RHETORICAL CATEGORIES HIGHLIGHT · REWRITE · RESOLVED BIAS: NONE SIGNAL: ACTIVE BUILD: VERIFIED
01 — The problem

We read persuasive language constantly. Most of it goes unnoticed.

News articles, social media posts, political coverage, corporate press releases, research PDFs — they're full of rhetorical devices designed to shape how we think before we've had a chance to evaluate the facts. Loaded language, emotional appeals, false presuppositions, artificial urgency.

The problem isn't that persuasion exists. It's that most readers don't have a way to see it happening in real time, on the page or document they're already reading.

"The radical regime has completely failed its citizens — and obviously, any reasonable person can see this devastating policy must be stopped now." Every article, every day — annotated below

I wanted to build something that turns critical thinking from a passive skill into an active one — a tool that sits in your browser and shows you the language as it's working on you, whether that's a news article or a PDF you've opened inline.

02 — How it works

Highlight. Analyze. Rewrite.

Select any sentence on a webpage or in a browser-rendered PDF. Neutralize identifies rhetorical devices with color-coded highlights, explains each one, and generates a neutral rewrite.

INPUT — ORIGINAL TEXT
The radical regime has completely failed its citizens. Obviously, any reasonable person can see this devastating policy must be stopped now.
↓ neutralized
RESOLVED · NEUTRAL REWRITE
The government has faced significant criticism over this policy. Analysts are divided on its effects, and some argue it should be revised or repealed.
Amplification
Intensifiers that exaggerate — completely, devastating, unprecedented
Emotion
Appeals to feeling over reason — heartbreaking, outrageous
Loaded language
Words chosen for connotation — regime, radical, invasion
Call to action
Urgency framing — must, act now, cannot wait
Presupposition
Assumes agreement — obviously, as everyone knows
Hedging
Vague attribution — some say, experts claim, many believe
Resolved
Neutralized output — bias removed
03 — Process

From idea to shipped in ~2 weeks.

I wore every hat on this project — defining the problem, designing the system, building the extension, and iterating on the UI. This was a casual side build, leaning heavily on Claude as a collaborator throughout: prompt engineering, icon design, the accessibility audit, even this case study. Here's how it came together.

DAY 1–3
Research + scoping
Mapped the rhetorical device taxonomy. Tested Claude API prompts for device detection. Defined the 7 categories based on what was reliably detectable and meaningfully distinct.
DAY 3–5
Extension architecture
Set up Chrome MV3 manifest, content script for DOM injection, background service worker for API calls. Kept the extension dependency-free — no frameworks, no bundler complexity.
DAY 5–8
Design system
Built a full color token system from scratch. Ran CVD simulation across 3 colorblindness types. Discovered pure color alone can't separate 7 categories — added secondary underline cues for WCAG 1.4.1.
DAY 8–10
Palette evolution
Original palette was too cyberpunk — cold, neon, high-contrast. Shifted to warm mauve + cream to match the product's intent: gentle, analytical, inviting critical thinking rather than alarming.
DAY 10–12
Prompt engineering
Iterated on the Claude prompt to reliably return structured JSON with device classifications, confidence scores, and neutral rewrites. Balanced sensitivity (catching devices) with specificity (avoiding false positives).
DAY 12–14
Polish + ship
Icon design iterations, accessibility audit, README, and brand assets. Added explanation panel to the popup showing the author's likely intent — not just what's flagged but why it matters.
04 — Design decisions

The choices that shaped the product.

DecisionOptions consideredWhat I chose and why
Color system Single accent, rainbow, semantic only 7 distinct hues + secondary underline cues. Color alone fails colorblind users — the underlines make each category distinguishable without it.
Dark palette Pure black, cool dark gray, navy, warm mauve Warm mauve #2A1F2E. Cold palettes felt like surveillance tools. Warm tones encourage reading, not alarming.
AI model GPT-4o, Gemini, Claude Claude Haiku — fast, cost-efficient, and more than capable of structured JSON output with strong rhetorical framing in context.
Extension scope Full-page auto-scan vs. highlight-to-analyze Highlight-to-analyze. Grounded in Google's PAIR Guidebook principle on user agency: when stakes are higher, user control should be foregrounded, not optional. Auto-scanning everything would feel paternalistic — the user should decide what to examine and when.
Rewrite tone Purely neutral, slightly formal, journalistic Journalistic neutral — factual, clear, no implied judgment in the rewrite itself.
05 — What I learned

What shipping fast with AI actually looks like.

This was a casual ~2-week build, and the speed was only possible because I used Claude as an active collaborator throughout — not just for the extension logic, but for the accessibility audit, icon design iterations, color system validation, and even the README. That changed how I think about AI tools: the ceiling isn't "can it write code," it's "how well can you direct it."

On AI product design: The highlight-to-analyze interaction wasn't just a UX convenience — it was a deliberate design decision rooted in Google's PAIR Guidebook on human-centered AI. The guidebook distinguishes between low-stakes automated flows (content recommendations) and higher-stakes ones where user control should be foregrounded. Rhetorical analysis sits in the latter category — it's an invitation to think critically, not a verdict handed down automatically. The user retains full agency over what they investigate and when.

On prompt engineering: The hardest part isn't getting good output once — it's making it consistent across wildly different input types. Political speech, corporate PR, and sports journalism all use rhetoric very differently. The prompt needed to understand context, not just pattern-match keywords.

On accessibility: I ran a proper CVD simulation using Machado 2009 matrices and discovered that with 7 categories across 3 colorblindness types, it's mathematically impossible to separate all pairs with color alone. This was humbling — and led to the underline cue system which ended up making the UI richer anyway.

On product tone: The first palette was too aggressive. Bright neon highlights on a dark HUD-style background made the tool feel like it was flagging dangerous content rather than inviting reflection. Shifting to warm mauve took one conversation and an afternoon — that kind of fast design iteration is where AI tools genuinely shine.
